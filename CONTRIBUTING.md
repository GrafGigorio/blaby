# Руководство по внесению вклада

Спасибо за интерес к проекту Voice AI Assistant! Мы рады вашему вкладу.

## Как внести вклад

### Сообщение об ошибках

Если вы нашли ошибку:

1. Проверьте, не была ли она уже зарегистрирована в issues
2. Создайте новый issue с описанием:
   - Что произошло
   - Как воспроизвести проблему
   - Ожидаемое поведение
   - Ваша среда (OS, Python версия, зависимости)
   - Логи ошибок (если есть)

### Предложение улучшений

Если у вас есть идея для улучшения:

1. Создайте issue с пометкой "enhancement"
2. Опишите проблему, которую решает улучшение
3. Предложите решение
4. Обсудите реализацию перед началом работы

### Pull Requests

1. **Форкните репозиторий** (если работаете с форком)

2. **Создайте ветку** для ваших изменений:
   ```bash
   git checkout -b feature/your-feature-name
   # или
   git checkout -b fix/bug-description
   ```

3. **Следуйте стандартам разработки**:
   - См. [DEVELOPMENT.md](DEVELOPMENT.md)
   - Следуйте стилю кода проекта
   - Добавьте документацию для новых функций
   - Обновите существующую документацию при изменении API

4. **Протестируйте изменения**:
   - Убедитесь, что все работает локально
   - Проверьте, что существующий функционал не сломан
   - При необходимости добавьте тесты

5. **Коммитьте изменения**:
   ```bash
   git commit -m "feat: описание вашего изменения"
   ```
   Используйте понятные commit сообщения (см. [DEVELOPMENT.md](DEVELOPMENT.md))

6. **Отправьте Pull Request**:
   - Укажите, что именно изменено
   - Свяжите с соответствующим issue (если есть)
   - Добавьте скриншоты/примеры если применимо

## Процесс ревью

- Ваш PR будет рассмотрен одним из maintainers
- Могут быть запрошены изменения
- После одобрения изменения будут влиты в основную ветку

## Области для вклада

### Приоритетные направления

1. **Улучшение производительности**
   - Оптимизация загрузки моделей
   - Кэширование результатов
   - Параллельная обработка

2. **Расширение функциональности**
   - Поддержка дополнительных языков
   - Выбор голосов для TTS
   - Сохранение истории разговоров
   - Голосовая активация (VAD улучшения)

3. **Улучшение пользовательского интерфейса**
   - Мобильная адаптация
   - Дополнительные настройки
   - Улучшение визуализации

4. **Документация**
   - Переводы документации
   - Примеры использования
   - Видео-туториалы

5. **Тестирование**
   - Unit тесты
   - Integration тесты
   - E2E тесты

6. **DevOps**
   - Docker контейнеризация
   - CI/CD pipeline
   - Автоматизированное развертывание

## Стандарты кода

### Python

- Следуйте PEP 8
- Используйте type hints
- Документируйте функции и классы
- Обрабатывайте ошибки явно

### JavaScript

- Используйте современный ES6+ синтаксис
- Комментируйте сложную логику
- Обрабатывайте ошибки асинхронных операций

### Коммиты

Используйте понятные сообщения:
- `feat:` - новая функциональность
- `fix:` - исправление ошибки
- `docs:` - изменения в документации
- `style:` - форматирование кода
- `refactor:` - рефакторинг кода
- `test:` - добавление тестов
- `chore:` - обновление зависимостей, конфигурации

Примеры:
```
feat: Добавлена поддержка английского языка в TTS
fix: Исправлена утечка памяти в WebSocket handler
docs: Обновлена документация API endpoints
```

## Структура Pull Request

Ваш PR должен содержать:

1. **Заголовок**: Краткое описание изменений
2. **Описание**: 
   - Что изменено и почему
   - Как это решает проблему/добавляет функциональность
   - Связанные issues
3. **Тип изменений**: 
   - Breaking changes (если есть)
   - Новые зависимости
   - Изменения в API

## Тестирование

### Локальное тестирование

```bash
# Запустите приложение
python main.py

# Проверьте основные функции:
# - Запись голоса
# - Распознавание речи
# - Генерация ответа
# - Синтез речи
```

### Проверка кода

```bash
# Установите инструменты для проверки
pip install black flake8 pylint

# Форматирование
black *.py

# Проверка стиля
flake8 *.py

# Линтинг
pylint *.py
```
