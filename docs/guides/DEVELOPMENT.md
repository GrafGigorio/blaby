# Development Guidelines

Этот документ описывает правила и лучшие практики для разработки проекта Voice AI Assistant.

## Структура проекта

```
blaBy/
├── main.py                  # FastAPI приложение и эндпоинты
├── stt_module.py            # STT модуль (Whisper)
├── stt_streaming_module.py  # Потоковый STT модуль (Vosk)
├── llm_module.py            # LLM модуль (Ollama)
├── tts_module.py            # TTS модуль (Edge TTS)
├── state_manager.py         # Управление состояниями диалога
├── static/
│   └── index.html           # Веб-интерфейс (SPA)
├── uploads/                 # Временные входные аудио файлы
├── outputs/                 # Сгенерированные аудио ответы
└── models/                  # Локальные модели (Vosk)
```

## Правила кодирования

### Python

1. **Стиль кода**: Следуйте PEP 8
   - Используйте 4 пробела для отступов
   - Максимальная длина строки: 100 символов
   - Импорты должны быть отсортированы (stdlib, third-party, local)

2. **Документация кода**:
   ```python
   def function_name(param1: str, param2: int) -> str:
       """
       Краткое описание функции.

       Args:
           param1: Описание параметра 1
           param2: Описание параметра 2

       Returns:
           Описание возвращаемого значения

       Raises:
           ValueError: Когда возникает ошибка
       """
   ```

3. **Типизация**: Используйте type hints везде, где возможно
   ```python
   from typing import Optional, List, Dict
   
   def process_data(data: List[Dict[str, str]]) -> Optional[str]:
       ...
   ```

4. **Обработка ошибок**:
   - Всегда обрабатывайте исключения явно
   - Логируйте ошибки с контекстом
   - Не используйте `except: pass` без крайней необходимости
   ```python
   try:
       result = risky_operation()
   except SpecificError as e:
       print(f"Ошибка выполнения операции: {e}")
       return None
   ```

5. **Асинхронность**:
   - Используйте `async/await` для I/O операций
   - Не блокируйте event loop долгими синхронными операциями
   - Используйте `asyncio.gather()` для параллельных задач

### JavaScript (Frontend)

1. **Стиль кода**: Используйте современный ES6+ синтаксис
   - `const`/`let` вместо `var`
   - Стрелочные функции для колбэков
   - Template literals для строк

2. **Комментирование**:
   ```javascript
   /**
    * Функция выполняет определенное действие
    * @param {string} param1 - Описание параметра
    * @returns {boolean} Результат операции
    */
   function functionName(param1) {
       // Логика функции
   }
   ```

3. **Обработка ошибок**:
   - Используйте try-catch для асинхронных операций
   - Всегда обрабатывайте ошибки WebSocket и Promise
   ```javascript
   try {
       await asyncOperation();
   } catch (error) {
       console.error('Ошибка:', error);
       showErrorToUser(error.message);
   }
   ```

## Архитектурные принципы

### Разделение ответственности

- **Модули** должны быть независимыми и переиспользуемыми
- Каждый модуль отвечает за одну функциональность
- Модули общаются через четко определенные интерфейсы

### Управление состоянием

- Используйте `StateManager` для управления состояниями диалога
- Не храните состояние в глобальных переменных (кроме инициализированных модулей)
- Состояние WebSocket соединения должно быть изолировано в handler функции

### Обработка аудио

- Все аудио операции должны быть асинхронными
- Освобождайте ресурсы (закрывайте потоки, останавливайте процессоры)
- Используйте правильные форматы и частоты дискретизации:
  - Vosk: 16kHz, PCM, 16-bit
  - Whisper: Поддерживает различные форматы

### Работа с моделями

- Инициализируйте модели один раз при старте приложения
- Переиспользуйте загруженные модели между запросами
- Обрабатывайте ошибки загрузки моделей gracefully

## Работа с зависимостями

### Добавление новых зависимостей

1. Добавьте зависимость в `requirements.txt`
2. Обновите версии существующих зависимостей только при необходимости
3. Проверьте совместимость с существующими зависимостями
4. Учитывайте ограничения (например, `numpy<2.0` для Whisper)

### Управление версиями

- Фиксируйте версии критических зависимостей
- Используйте диапазоны версий для незначительных обновлений
- Документируйте причины фиксации версий

## Логирование

### Стандарты логирования

- Используйте понятные префиксы: `[1]`, `[2]`, `[STT]`, `[LLM]`
- Логируйте начало и конец важных операций
- Включайте контекст в логи (имена файлов, состояния)
- Используйте разные уровни: info, warning, error

```python
print(f"[STT] Распознавание речи из файла: {audio_path}")
print(f"[STT] Результат: {transcribed_text}")
```

### Отладочная информация

- Выводите промежуточные результаты для отладки
- Группируйте логи по модулям
- В production используйте структурированное логирование

- Ограничивайте размер загружаемых файлов

### WebSocket

- Валидируйте все сообщения от клиента
- Ограничивайте частоту отправки сообщений
- Обрабатывайте отключения gracefully

## Отладка в VS Code

### Настройка отладки

В проекте настроены конфигурации отладки в `.vscode/launch.json`:

1. **Python: FastAPI Main** - запускает `main.py` напрямую
2. **Python: FastAPI with Uvicorn** - запускает через uvicorn с auto-reload (рекомендуется для разработки)

### Как использовать

1. Откройте проект в VS Code
2. Установите Python интерпретатор из `venv`:
   - `Cmd+Shift+P` (Mac) или `Ctrl+Shift+P` (Windows/Linux)
   - Выберите "Python: Select Interpreter"
   - Выберите `./venv/bin/python`

3. Установите breakpoints (красные точки) в коде:
   - Кликните слева от номера строки

4. Запустите отладку:
   - `F5` или нажмите зеленую кнопку "Start Debugging"
   - Выберите конфигурацию из списка

### Отладка WebSocket

Для отладки WebSocket эндпоинтов:

1. Установите breakpoint в `main.py` на строке `await websocket.receive_json()`
2. Откройте браузер на `http://localhost:8000`
3. Запустите отладку в VS Code
4. Нажмите "Начать диалог" в браузере
5. Выполнение остановится на breakpoint

### Полезные команды отладки

- `F5` - продолжить выполнение
- `F10` - step over (выполнить строку)
- `F11` - step into (войти в функцию)
- `Shift+F11` - step out (выйти из функции)
- `Ctrl+Shift+F5` - перезапустить отладку
